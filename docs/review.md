## 處理原則

- **防偽本版先不做**：HMAC 防偽與「緊急廣播要收到兩包才顯示」的鎖造成多個嚴重問題（下表 #1～#6），已移除，協定回到沒有防偽尾碼的 v2（模板封包 8 bytes、約 2.4 秒）。程式碼保留在 git 歷史（commit `2098029`）。日後重新設計的方向見文末。
- **保留 William 的解碼改進**：分段累積確實提升吵雜環境的成功率，改成可開關的 `RxOptions.accumulation`（預設開啟），baseline 維持 PoC 的忠實移植。
- **保留一鍵接收介面與依手機語言自動選字幕語言**；月台判斷改回主畫面顯示。

## 防偽：日後重新設計的方向

本版不做防偽，原因與評估如下，供日後參考：

- **限制**：單向廣播（手機不能回傳）、乘客手機常離線、程式碼公開、每多 1 byte 封包多約 0.12 秒。放在乘客手機上的任何密鑰都等於公開，所以對稱式 MAC（HMAC）無法防偽。
- **非對稱簽章（Ed25519）**：最安全，但簽章 64 bytes，封包多約 7.7 秒。
- **TESLA（延遲揭露金鑰）**：安全且封包只多數 bytes，但驗證要等金鑰揭露（至少比可容忍的時鐘誤差晚，約 15～30 秒）。
- **時間槽一次性令牌（雜湊鏈）**：收到就驗證、每則多約 8 bytes（約 1 秒），擋得住偽造新廣播與重播舊錄音；弱點是攻擊者在現場、同一個時段內把真廣播的內容換掉，送給沒收到真廣播的手機（可在真的重送到達時偵測為內容衝突）。
- **不論哪一種**，緊急警報都應「立即顯示、標示驗證狀態」，不能因驗證而延遲或消失。

## 落地前要確認的事項（非程式問題）

1. 車站天花板廣播喇叭常見規格在 20 kHz 是 −10 dB、−3 dB 只到 15～16 kHz，部分型號只到 18 kHz；月台號角喇叭可能更低。需以「硬體診斷」的掃頻現場量測，部分站點可能需要加裝小型高音喇叭。
2. 數位／IP 廣播系統若使用語音編碼或 16～32 kHz 取樣，會切掉 16 kHz 以上，訊號要從擴大機輸入端注入，需設備廠商配合。
3. 手機麥克風的高頻響應差異大，需約 10 款手機的實測矩陣（含 44.1 kHz 的 Android）。
4. 導盲犬與其他動物聽得到 19.5 kHz；需評估並以最小可收音量為原則。
5. 多月台同時廣播：目前以佇列一次播一則，日後可讓不同月台使用不同頻段。
6. iPhone 鎖屏後無法接收，乘客需保持頁面開啟；需在月台張貼 QR Code 說明，長期以原生 App 支援背景接收。
7. stationId 只有 1 byte（256 站），跨營運單位需擴充。
8. 本系統是官方廣播的輔助，緊急狀況仍以現場廣播與站務人員指示為準，需在介面與文件中註明。
